# CSTI — Cross-Strait Tension Index (양안긴장지수)

GDELT 사건 데이터 위에 LLM 전수 코딩을 얹어 **대만–중국 / 대만–미국** 양자 긴장도를 날짜별로 내는 대시보드.

**이것은 방법 시연이다. 측정치로 인용할 수 없다.** 이유는 `codebook.md` §11에 있다.

---

## 무엇에서 왔나

[gais-kbti](https://github.com/gaiscenter/gais-kbti)(한국 양자관계 긴장지수)의 포크다. 기준국만 한국 → 대만으로 바꿨고, 두 저장소는 이후 따로 간다.

그대로 가져온 것:

- **채널 정의** — 군사·외교를 사건 코드가 아니라 **행위자 유형**(MIL/GOV)으로 가른다. 사건 코드로 가르면 그 코드들의 Goldstein 값이 한쪽으로 쏠려 있어 지수가 항상 극단으로 간다
- **감사 계층** — 기사 원문을 다시 읽혀 GDELT 오분류를 거른다
- **수축** — `e/(e+5)`. 증거가 얇으면 값을 0 쪽으로 당긴다
- **코드집과 경계 규칙** — `codebook.md` §7~§9

새로 쓴 것(검증 없음): `codebook.md` §3 V1 관련성, §4 V2 상대국.

## 지수

```
CSTI = −1 × [ Σ(Goldstein × Mentions) / Σ(Mentions) ] × e/(e+5)
```

양수는 긴장, 음수는 협력. `threat`은 **상대 → 대만**, `response`는 **대만 → 상대**이고, **방향 라벨이지 적대 여부가 아니다** — 미국의 무기 판매는 threat 방향에 들어가지만 Goldstein이 양수라 지수는 음수(협력)로 나온다.

## 파일

| | |
|---|---|
| `pipeline.py` | 매일 실행. GDELT 조회 → 기사 수집 → 감사 → 지수 → `csti_output.json` |
| `llm_coder.py` | 코드북 기반 기사 코딩. 프롬프트는 `codebook.md`에서 기계 생성 |
| `codebook.md` | **코더의 유일한 지침.** 바꾸면 지문이 바뀌고 전 구간 재코딩이 필요하다 |
| `backfill_code.py` | 날짜 범위 전수 코딩 (API 비용은 여기서 난다) |
| `build_day_commentary.py` | 날짜×상대국 해설. 증거 3건 미만이면 해석하지 않고 사실만 적는다 |
| `index.html` | 대시보드 |

## 비밀값

`ANTHROPIC_API_KEY` · `GCP_KEY`(서비스 계정 JSON) · `GCP_PROJECT`.

**키를 저장소에 넣지 않는다.** 콘솔에서 Actions secrets 로 직접 넣는다.

## 알려진 제약

- **군사 채널이 얇다.** 30일 관문 측정에서 대만–중국 군사 사건이 하루 3.2건이었다(한국–북한 10.4건). 7일 누적창이 걸려 있지만 일별 군사값은 거칠다
- **대만–일본은 넣지 않았다.** 하루 군사 0.1건·외교 0.2건으로 의미가 없었다
- **원자료와 코딩 계열은 다른 것을 센다.** 원자료는 GDELT 사건, 코딩 계열은 사람이 읽을 수 있는 기사 중 관련 판정된 것. 한국 쪽에서 둘의 차이가 컸다
- **호칭 정규화 목록이 잠정이다.** `build_day_commentary.py` 의 `_TERMS`. 최종 목록은 사람이 정해야 한다
